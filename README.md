# Skin Tool 회고록
**Project Zomboid 차량 스킨 적용 시뮬레이터**

---

## 프로젝트 개요

Skin Tool은 Project Zomboid의 차량 모드 커뮤니티를 위해 만든 3D 뷰어입니다.
FBX 모델에 PNG 텍스처를 실시간으로 적용해서 스킨이 차량에 어떻게 보일지 미리 확인할 수 있습니다.
일반적인 경우 스킨을 폴더에 새로 넣고 적용 시킬 때 마다 게임을 재부팅 해야합니다.

귀찮음에서 출발한 개인 프로젝트입니다.

원래는 팩션(멀티플레이 내 소규모 그룹) 내부용으로 시작했는데,
서버단위로 규모가 커지면서 웹과 데스크탑 모두 지원하게 되었습니다.

**목표:**
- 스킨 제작자가 즉시 확인 가능한 도구
- 설치 간편 (웹으로 열기 또는 데스크탑 exe)
- 모바일도 지원 (아이폰에서 PWA처럼 사용)
- 팩션 멤버들이 쉽게 공유 가능
- 귀찮음 해소

---

## 기술 스택

- **Frontend:** Three.js (3D 렌더링), FBXLoader (모델 로드)
- **Bundler:** esbuild (모듈 번들링, 아이폰 호환성 우회)
- **Desktop:** Tauri v2 (OS 네이티브 앱, exe 싱글 파일 배포)
- **Web/Mobile:** PWA + Service Worker (스마트 캐싱 전략)
- **Asset Management:** Base64 인라인 + 실제 파일 트리 분해

## 주요 문제와 해결

### 1. **FBX 모델 좌표 이상 — 디버그 모드 탄생**

**상황:**
fbx 모델링 파일을추가하려는데, 메인 장면에서 모델 위치가 완전히 틀어졌습니다.
두개이상의 fbx를 사용하는 모델들은병합하면서 원점과 스케일이 맞지 않는 문제가 생겼습니다.

**처음 시도:**
- 모델을 Three.js에서 로드 후 하나로 병합
- geometry 좌표 정규화
- vehicles.json에 stockSize 기록해서 내보내기 시 원본 크기 유지

하지만 여전히 다양한 위치 문제들이 존재했습니다.

**해결책 — 디버그 모드 개발:**
이 문제를 해결하기 위해 **디버그 모드를 처음부터 만들었습니다.** 
왼쪽에 섹션을 따로 두고, 디버그 패널을 추가해서:
- 모델의 position, scale, rotation을 실시간 슬라이더로 조정
- 값을 작은 단위로 적용하면서 맞는 위치값을 파악
- 각 값을 콘솔에 출력해서 빠르게 복사 & 붙여넣기 후 · 테스트

이 패널만으로 **몇 시간 소요될 수 있는 문제를 몇 분 안에 해결했습니다.**

**결과:**
- 하나의 fbx로 모델 재생성
- 디버그 패널은 배포 후에도 개발자용(복잡한 단축키로 해당기능을 숨김)으로 유지 (모바일에서는 자동 숨김)
- 다른 차량 추가 시에도 이 패널을 사용해 빠르게 위치 조정 가능

**배운 점:**
"막혔을 때 고민하지 말고 보이게 만들어라." 
3D 좌표 같은 값들을 프로그램 내 기능(슬라이더 등)으로 가시화하면, 문제파악이 명확해집니다.

### 2. **아이폰 호환성 깨짐 — data: URL 모듈 임포트 제약**

**문제:**
아이폰 Safari에서 앱을 열면 "불러오는 중" 화면에서 멈춤. PC는 잘 되는데 모바일만 안 되었습니다.

**원인 분석:**
아이폰 Safari는 보안상 이유로 `import()` 함수로 data: URL에서 동적 모듈을 로드하는 걸 막습니다.
그래서 Three.js와 FBXLoader 같은 라이브러리들이 아예 실행되지 않았어요.

**해결책:**
- esbuild로 Three.js + FBXLoader를 하나의 거대한 번들로 미리 컴파일
- 동적 임포트맵 완전 제거
- 번들을 일반 `<script>` 태그로 인라인 (data: URL이 아닌 일반 스크립트)
- 결과: vendor/viewer-deps.js (1.2MB)로 관리

**트레이드오프:**
- 파일 크기가 좀 더 커졌지만, 모든 플랫폼에서 동작하게 됨
- 초기 로딩 시간은 약간 늘었지만, 한 번만 로드되고 캐시됨

**배운 점:**
크로스 플랫폼 개발할 때는 "표준에 맞다"고 해서 모든 환경에서 작동하는 게 아닙니다.
iOS의 보안 제약이 오히려 번들링을 강요했고, 덕분에 더 안정적인 배포 형태가 되었습니다.

### 3. **아이폰 메모리 부족 — 54MB 파일 로딩 멈춤**

**문제:**
PC에서는 54MB 버전이 문제없이 도는데, 아이폰에서 열면 "불러오는 중"에서 고정됩니다.
Safari의 메모리 한계가 원인으로 추정되었습니다.

**해결책 — 단계별 최적화:**

1. **텍스처 해상도 축소**
   - 스킨 이미지: 1024×1024 → 512×512
   - 일부 모델 텍스처: 4096px → 2048px

2. **stockSize 메타데이터 추가**
   - vehicles.json에 `stockSize: 512` 기록
   - 화면에서는 축소된 버전으로 미리보기
   - 사용자가 "내보내기"할 때는 원본 크기(1024×1024)로 제공
   - 스킨 제작자는 최종 결과물의 품질을 보장받음

3. **결과:**
   - 54MB → 27.4MB (압축 전)
   - 최종 gzip: 7.0MB
   - 아이폰에서 안정적 로딩 가능

**설계 철학:**
"미리보기와 최종 출력은 다를 수 있다." 모바일 사용자는 대략적인 확인만 필요하지만,


**배운 점:**
모바일 최적화는 단순히 "파일을 작게 만드는 것"이 아니라,
사용 목적에 따라 품질을 선택적으로 줄이는 것입니다.

### 4. **Tauri 데스크탑 배포 완료**

**배포 방식:**
Tauri v2를 사용해 데스크탑 exe 싱글 파일로 배포했습니다.

**커스텀 구현사항:**

- **아이콘 제작:** SKIN_TOOL_BETA_ICO.png를 직접 제작
  - 16~64px: 글씨 없는 크롭 (픽셀아트 토끼 + 빨간 차)
  - 128px 이상: 전체 디자인 유지

- **초기 로딩 화면 (스플래시):** 직접 제작한 1280×720 이미지
  - 백수왕(팩션 아트디렉터)이 제작한 스플래시 이미지 사용
  - 가장자리 반투명 처리로 배경이 비쳐 보이도록 연출
  - Tauri 네이티브 창으로 페이드인 4초 → 메인 창 표시

- **스플래시 창 크기 자동 계산:**
  - main.rs에서 PNG 파일의 IHDR 헤더를 직접 파싱
  - 이미지 비율을 자동 계산 (모니터 가로폭의 36%, 420~1100px 범위)
  - 하드코딩하지 않아서 이미지만 바꾸면 비율 자동 조정

- **드래그 앤 드롭:**
  - 창 아무 데나 이미지를 드래그해서 떨어뜨리면 스킨 적용
  - Tauri에서 dragDropEnabled를 false로 설정해야 작동

- **결과:** SkinTool.exe (싱글 파일, exe 만으로 배포 완료)

**배운 점:**
데스크탑 앱도 세부 UX (스플래시, 아이콘, 드래그)를 신경 쓰면 훨씬 전문적으로 느껴집니다.

### 5. **아이폰 호환성 방법론 재검토**

**초기 계획:**
Tauri로 iOS 앱도 만들려고 했지만, Tauri v2는 iOS 빌드에 macOS + Xcode가 필수였습니다.
가용한 맥이 없어 불가능했습니다.

**대안 모색:**
iOS 사이드로딩, TestFlight 등 여러 방법을 검토했지만, iOS의 제약으로 인해 모두 비현실적이었습니다.

**최종 결정: PWA 배포**
"앱 설치"에 집착하기보다는, 누구나 웹 주소로 접근 가능한 PWA로 방향 전환했습니다.

**PWA 구현:**
- index.html + manifest.json + sw.js (Service Worker)
- 초기 로딩: 1.6MB 프리캐시 (셸)
- 차량 전환 시: 0.3~7.5MB 추가 다운로드 + 자동 캐시
- 캐싱 전략:
  - JSON: 네트워크 우선 (항상 최신 데이터)
  - FBX/PNG/JS: 캐시 우선 (빠른 로딩)

**아이폰에서 사용:**
1. Safari에서 `https://jobless-fish.github.io/SkinTool.BETA_M/` 열기
2. 공유 버튼 → "홈 화면에 추가"
3. 앱처럼 사용 가능 (오프라인에서도 캐시된 차량 열 수 있음)

**배운 점:**
제약이 오히려 더 나은 솔루션을 낳았습니다.
설치 없이 누구나 접근 가능한 PWA가, 앱 설치보다 훨씬 더 많은 사람들에게 도달했을 겁니다.

### 최종 상태

- **PWA:** 웹/모바일 사용자용 (아이폰에서 홈 화면에 추가)
- **싱글 HTML 백업:** 인터넷 연결 불가능한 상황용 (base64 전체 내장)

각 형식이 다른 목적을 가지고 있으며, 모두 필요했습니다.

## 개발 과정에서 얻은 인사이트

1. **"보이게 만들면 해결된다"**
   - 추상적인 3D 좌표 → 슬라이더로 가시화 → 디버그 모드 완성
   - 문제 해결 속도가 극적으로 빨라짐

2. **"제약이 최고의 디자인 도구"**
   - iOS의 임포트 제약 → 더 안정적인 번들링 전략
   - 메모리 부족 → stockSize 메타데이터 설계
   - exe 배포 불가 → 웹 PWA의 탄생

3. **"플랫폼별 특성을 이해해야 한다"**
   - PC: 성능과 기능 중심
   - 모바일: 메모리와 네트워크 최적화
   - 각각 다른 최적화 전략 필요

4. **"여러 배포 형식은 선택이 아니라 필수"**
   - Tauri exe (설치형, 오프라인)
   - PWA (웹, 설치 불필요)
   - 싱글 HTML (백업, 인터넷 없을 때)
   - 사용 상황에 따라 모두 필요

## 마치며

Skin Tool의 개발 과정은 **단순한 "뷰어 만들기"가 아니라 "다양한 제약 속에서 해결책 찾기"였습니다.**

- FBX 좌표가 안 맞았을 때 → 디버그 모드 개발
- 아이폰이 동작하지 않았을 때 → 번들링 전략 재구성
- iOS 빌드가 불가능했을 때 → PWA라는 더 나은 솔루션 발견
- 메모리가 부족했을 때 → 품질을 나누는 설계 패턴 개발

이 모든 제약들이 오히려 더 튼튼하고, 더 많은 사람들이 사용할 수 있는 도구를 만들어주었습니다.

특히 **디버그 모드는 단순히 "개발 도구"가 아니라, 이 프로젝트의 포인트 입니다.**
"숨겨진 것을 보이게 만들고, 그것을 조정할 수 있는 권한을 준다."

사용자들도 디버그 패널을 통해 자신의 모델을 직접 미세 조정할 수 있으며, 이는 단순한 "스킨 뷰어"를 넘어 "스킨 조정 도구"로 진화시켰습니다.
